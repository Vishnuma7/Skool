Last month Sarah copied numbers from websites into Excel 31 times: exchange rates, the weather near suppliers and holiday calendars. That's over two hours of copy-and-paste. In this lesson you'll learn what an API is, using a waiter in a restaurant, and you'll make two real API calls from your own browser. No code and no sign-up.

In this video, you'll see:

  • How an API works: the customer, the waiter and the kitchen
  • A live weather call for Shenzhen, and how to read the JSON answer like a shopping list
  • A live currency call (USD to yuan and pesos), and the currency that never came back
  • GET vs POST, and status codes as restaurant receipts
  • API keys as hotel key cards, and where Odoo keeps them

Key takeaways

  1. An API is a waiter: request, endpoint, parameters, response.
  2. JSON is a labelled shopping list; status codes are receipts.
  3. GET is safe, POST needs a signature, and keys are key cards.

Key terms

  • API: a waiter. You give your order; it brings back exactly what you asked for from the kitchen.
  • Endpoint: one dish on the menu, e.g. /forecast or /latest.
  • Parameters: the order details after the ? in a web address, joined with &.
  • JSON: a labelled shopping list, e.g. "timezone": "Asia/Shanghai".
  • GET / POST: asking (safe, changes nothing) vs submitting (creates or changes something).
  • Status code: the receipt. 200 OK · 401 wrong key · 404 wrong address · 429 too many orders.
  • API key: a hotel key card. It opens only certain doors and can be cancelled.

File: Attach Video_03/V03_Activity_API_Treasure_Hunt.xlsx · Label: Activity: API Treasure Hunt (Excel)
Text

Time: about 30 minutes · No code, no sign-up: just your web browser. Works in Excel or Google Sheets.

Step by step

  1. Download the workbook and read the Instructions sheet.
  2. Treasure_Hunt: open each of the 3 web addresses in a new browser tab and answer the questions in the yellow cells. Live numbers change daily, so your answers will be different from anyone else's.
  3. Decode_JSON: read a saved weather answer from a stormy week in Shenzhen and copy the values into the table. The sheet checks your work and works out a risk level.
  4. Status_Codes: match each status code (the "receipt") to its meaning.
  5. GET_or_POST: for each BrightLeaf task, decide whether Stocky is asking (GET) or submitting (POST).
  6. My_Suppliers: enter 3 to 5 of your suppliers' cities, coordinates and currencies. The sheet builds ready-to-click weather, currency and holiday links for each one.

Tip: in Chrome, tick Pretty-print at the top of the answer page to make it readable. You can't break anything: these APIs only answer questions.

You're done when: your total score shows on the Instructions sheet and the links on My_Suppliers open for at least 3 of your suppliers.

Text

One cell in BrightLeaf's stock sheet said "21". It cost about $1,840. The number was right; the unit was missing. Before Stocky can read your data, it has to be clean. In this lesson you'll learn what a database really is (you already know 90% of it from Excel), build Stocky's two starter tables in Google Sheets and clean up a messy export live.

In this video, you'll see:

  • Why a database is just a super-organised workbook, and why every record needs an ID
  • The supplier who existed three times, and how one ID fixed it
  • Building the Suppliers and Stock_Log tables in Google Sheets, with dropdowns, checkboxes and formulas
  • The five golden rules of agent-ready data
  • A messy stock export cleaned up in 7 fixes

Key takeaways

  1. A database is a super-organised workbook: tables, rows (records) and columns (fields).
  2. Use IDs, not names, to connect your tables.
  3. Follow the five golden rules: agents read values, not formatting.

The five golden rules

  1. One table per thing
  2. One header row, in row 1
  3. One fact per cell
  4. A unique ID on every row
  5. Consistent types and units

Bonus: no merged cells, no colours that carry meaning, no totals inside the table.

Key terms

  • Database: a super-organised workbook.
  • Table / Record / Field: a sheet / a row / a column.
  • Unique ID: like a passport number, e.g. SUP-002. Names vary; IDs don't.
  • Relationship: an ID in one table pointing to a row in another (Stock_Log → Suppliers).
  • Data validation: dropdowns and checkboxes that stop mess at the door.

Text

Time: 30-40 minutes · Works in Excel or Google Sheets.

Step by step

  1. Messy_Export: just look, don't fix anything. How many problems can you spot in 2 minutes?
  2. Problem_Spotter: 12 problems are listed. Pick the problem type from the dropdown and write how you'd fix it.
  3. Clean_Stock_Log: rebuild the messy data as a clean table: one row per product, one fact per cell. Rows 2-3 are done as examples.
  4. Suppliers: complete the yellow cells. Tip: SUP-006 is in the same city as SUP-004.
  5. Checklist: score the clean BrightLeaf table and one spreadsheet from your own job against the 13 clean-data rules.
  6. My_Company: design a clean, agent-ready version of a spreadsheet you use every week.

Want to follow the video step by step? In Google Sheets, go to File → Import → Upload, choose this file and pick Insert new sheet(s). Then practise the 7 fixes on the Messy_Export tab.

You're done when: Clean Stock Log shows 8/8 and Suppliers shows 6/6 on the Instructions score panel.
